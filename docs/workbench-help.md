# 工作台使用与本次更新（2026-10-28）

页面顶部新增可展开的“帮助”，按模块解释用途、操作和限制。

## 数量和提醒更新

页面每 3 秒读取统计和特别关注提醒，不改变正在编辑的表单或搜索条件。请求失败会提示旧数据。采集本身约每 15 秒一轮，读取和入库还需要时间，因此不是微信发送瞬间就更新。

## 配置和使用 AI

1. 在“AI 模型配置”填 API 基础地址、模型名称和 API Key。基础地址保留供应商要求的 /v1 等前缀，不附加 /chat/completions。
2. 勾选允许手动调用并保存；点击“测试已保存配置”。测试只发送固定文字，不发送聊天。
3. 在“寻找历史”选择少量消息作为证据，在“历史初始化任务”创建所选消息分批范围。
4. 等窗口准备完成，刷新任务，预览窗口模型输入并核对隐私替换，然后点击“用 AI 提炼此窗口”。
5. 结果经结构、引用范围、证据版本、隐私映射版本校验后进入“有证据的记忆”，标为 AI 提炼。失败不会自动重复付费调用；在任务内检查并按需重试。

密钥以 Windows 当前用户 DPAPI 加密保存在 data/ai-settings.json；接口不回显密钥。留空保留旧密钥，更换地址需重新填写。取消允许并保存可禁用新请求，删除配置会删除本地保存的密钥。已发出的请求不能撤回。

使用已有 httpx，无新增依赖。采用兼容接口 POST /chat/completions，要求 JSON 输出，禁止自动重定向。接口约定参考 [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 和 [JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。不同供应商的模型名和基础地址应按其官方说明填写。

## 微信机器人是否需要 AI

不需要。现有实际通路是：采集新增对方消息 → 命中有效特别关注 → 生成提醒 → 已启用的通知程序向扫码本人发送通用待查看提示。机器人通道此前经过手机接收和弹通知实测。

搜索历史不会触发推送，历史导入不会触发推送；不是所有新消息都会推送。同一近期上下文可能合并为一张提醒，已经发过的提醒不会重复发送。机器人需要有效登录、通知程序运行及有效待发送提醒。自动 AI 判断每条新消息与普通记忆关联后推送，尚未接通；保存 AI 配置不会启用这项功能。

128 项 Python 测试通过；前端构建与浏览器桌面、窄屏流程通过。浏览器验证覆盖无点击情况下数量自动变化、帮助展开、配置保存和清除密钥输入、模拟连接测试、原有搜索和记忆工作流。模型调用使用隔离数据和模拟传输；用户真实接口、余额、输出质量需填写配置后验证。本次没有发送真实聊天给模型。
