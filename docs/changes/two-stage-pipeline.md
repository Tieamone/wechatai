# 两段式记忆流水线设计草案

日期：2026-11-03。基线：PR #18，数据库 v24。本文件只提出设计，不实施新状态机、不升级真实库、不改变日常 v2、不启用角色处理、不写入单价、不调用模型。粗提及 review-v1 提示词须用户和审阅者确认后才可用于真实调用。

## 1. 现有行为与差距

现有 `create_memory` 把模型通过结构、引用、代号及角色校验的结果直接创建为 `memory.status=active` 并写 FTS。现有完整性状态是 active、stale（来源修订）、incorrect（标错）、superseded（被更正版替代）；没有候选隔离或 AI 审核状态。`memory_review` 另存人工确认版本，`feedback` 保存版本化动作，不决定召回资格。

`memories.listing` 默认搜索全部 active；pending/confirmed 只是人工核对分类。`associations.rank_candidates` 对全部 active 排名，没有人工确认过滤；证据必须早于触发窗口，且修订一致。普通关联再由判断模型决定是否值得提醒；`notifications` 另检查已确认的**关联**、自动处理开关、证据与通知策略。关联 confirmed_model 不等于记忆已人工确认。特别关注命中也不要求记忆人工确认。

`temporal_kind` 只有 preference、plan、past_event、fact、unknown，表示事项类型。它参与草稿/模型契约、指纹、显示与更正；现有召回没有使用它加权，也没有 valid_until、临期提升或日历到期调度。偏好可能短期，计划可能长期，不能把该字段改名或把 plan 直接当 short。应保留事项类型，新增独立 retention_category 与生命周期。

现有 job 从 pending→running→prepared，隐私问题可到 blocked_privacy，准备失败到 failed；提炼领取后 extracting，返回提交成功到 validated_model，失败到 failed，预算拒绝退回 prepared。validated_model 只说明现有提炼提交完成，不说明语义经过 AI 审核。

## 2. 业务状态与查询资格

采用候选表隔离，避免用一个 status 混合来源有效性、人工确认和审核进度。

| 对象/状态 | 正常搜索 | 召回 | 主动提醒 |
| --- | --- | --- | --- |
| 暂存候选 candidate | 否 | 否 | 否 |
| 拒绝 rejected | 否，审计详情可查 | 否 | 否 |
| 旧记忆 legacy_pending | 是 | 仅用户搜索/回忆用途 | 否，等待 AI 审核 |
| AI 核对 ai_reviewed | 是 | 是 | 满足证据、风险、模型一致和通知策略时允许 |
| 已过期 expired | 是 | 衰减但不归零 | 不再发送旧约定的日历推送；有新消息明确涉及旧事时可按衰减评分进入关联判断，须说明已过期 |
| 完整性 stale/incorrect/superseded | 仅显式更正/历史详情 | 否 | 否 |

AI 审核不依赖人工 confirmed。人工确认单独保留，不能冒充 AI 审核结果。待精修的候选不写 memory_fts。精修通过后，一个事务建立正式 memory、完整证据、FTS、生命周期与审核来源；失败整批不出现半条正式记忆。候选和记忆不物理删除；用户主动删除需另立删除语义，不在本轮设计中暗中实现。

“只搜索”是一种权限门：用户搜索可用，后台的新消息提醒候选查询不能把它放入主动派送队列。不得仅把评分调低来代替这道门。

## 3. 拟议一次迁移（v25，未实施）

同阶段合并一次 schema 变更，沿用工作台/采集/机器人锁、空间检查、在线备份和五份保留。以下是字段设计，不是已运行 DDL：

- `model_profile`：模型 code、供应商与接口标识、明确解析的快照身份、加密凭据引用、粗提/审核角色、顺序、每模型参数 JSON/能力版本、额度与 90% 上限、free_tier_only_confirmed、数据条款和用完即停确认时间。费率归各 profile，空值仍禁止金额预算模式。
- `memory_candidate`：job/request/input_hash、隐私处理后的摘要与原始结构、source_ref→消息/修订快照、retention_hint、window_age、相对日期结构、粗提来源 profile/模型/提示词版本、candidate/rejected/promoted 状态、独立幂等键。只留本机，不参与普通查询。
- `memory_ai_review`：候选和记忆版本、证据哈希、审核员类型、真实模型快照、提示词和契约版本、输入指纹、预算账本 ID、时间、证据支持/类别/有效期/敏感标注/置信度及一句理由。追加式记录，不覆盖旧审核。
- `memory_lifecycle`：memory_id/版本、ai_reviewed/expired/legacy_pending、long/short、valid_until/grace_until、date_precision、来源消息锚点、提醒资格及降级原因。不能改变完整性 status。
- `quality_feedback`：动作 correct/low_value/outdated、显式事实判断、记忆版本、证据快照、更正前后 ID、提醒 ID、抽样任务 ID。现有 feedback 与 memory_review 保留并可兼容读取，不复制正文。
- `quality_control`、`sample_run/sample_item`：只搜索模式、触发错误率的分子/分母/时间范围/原因；随机种子、抽样概率、风险层、当时版本和证据哈希。抽检计划可重启恢复，不自动生成用户结论。

旧 active 记忆迁入 legacy_pending：保留原文、指纹、人工确认、搜索能力和版本，不伪造审核通过；先禁用主动提醒，后台按预算补 AI 审核。旧来源已失效的记录保持失效。候选提交路径、普通搜索、召回、特别关注、普通提醒、手动真实发送都必须使用统一资格函数，避免只在 UI 隐藏。

迁移验收包括恢复后旧列逐行指纹一致、候选完全不进入搜索/召回/派送、人工 confirmed 与 AI 审核互不替代、所有发送入口遵守只搜索模式。真实库升级仍需单独部署流程，本轮只演练副本 v22→v24。

## 4. 粗提：便宜快模型

草案见 `extraction-v4-draft.md`。以 v3 长期价值过滤为基础，不放宽闲聊过滤。窗口年龄由系统按最新有效消息事件时间计算：距发起时刻达到 60×24 小时即 old，否则 recent；阈值可配置，默认 60 天，未调优。时间缺失继续阻断，不猜 recent。old 窗口出现 short 结果时按契约拒绝该条并记录，不降格成长记忆。

粗提输出只是候选；retention_hint 为 long/short/unsure。允许空结果，窗口级 skip_reason 只用于诊断，不能当用户价值标签。人物代号不还原后出站。精确日期在文本内也须替换为请求限定的 DATE 代号；不能只删 event_time 却让正文中的年月日透出。DATE 的检测、映射、指纹、引用校验和出站阻断须一起扩展现有隐私契约。

日期只给相对结构或请求 DATE 代号。系统依据对应 source_ref 的本地事件时间解析，不依据调用当天解析历史“明天”。本月/下月遇不存在日期、多个约定、时区不明或来源冲突时标为 unresolved，只搜索，不悄悄钳制到月底。不让模型返回绝对年月日或自行运行日期工具。

## 5. 精修/审核：更强且不同的模型

草案见 `review-v1-draft.md`。输入只包含本次隐私处理后的证据、摘要、断言、事项类型、粗提保留倾向、相对日期结构及请求限定代号；聊天始终是数据。模型不得看到真实映射值、账号路径、绝对日期或其他候选无关摘要。

审核结果含 supported/partial/unsupported、long/short/trivial/unsure、有效期档位、健康/财务/隐私代号标注、置信度及一句理由。模型置信度不能代替证据，也不用于当前召回调参。模型意见不一致、部分支持或置信度低于 0.8（默认，未调优），最多只搜索并进入抽检池；不自动改成 direct，不改写原引用。

普通记忆至少一个与粗提不同的审核模型。健康、财务、隐私代号使用更严门槛：必须找到直接原文陈述依据，不能只凭推断；主动提醒必须两个不同审核模型结论一致，且审核模型都不同于粗提。粗提“提出了一条候选”本身不算审核通过一票。相同真实快照的两个别名不能算两个模型。reported 不自动降级：有明确本人原文支持的转述可以通过；仅第三方猜测不能冒充本人健康或财务事实。

系统计算 valid_until，不接受模型伪造绝对时间。短期无约定日时暂用 14 天/60 天档位（未调优），锚定支持该事实的消息时间，不按入库时间续命。带明确约定日的，到本地约定日结束为 valid_until；额外五个完整本地日为 grace_until，宽限内按正常处理，超过后变 expired。非约定短期不擅自获得五天宽限。审核发现已过期仍保留正式历史记忆和证据，但状态 expired，不能补发旧到期提醒。

## 6. 召回权重和提醒

现有词面/人物分仍作为相关性底分，不在无标签条件下改 IDF。未来可组合：`相关性 × 保留权重 × 时间因子`；长期 1.0，短期 0.6，临近约定提升 1.5 倍（提前 2 天到约定日，参数允许 1–2 天），均未调优。此默认下短期临期为 0.9，长期仍较高。

宽限内时间因子为 1。超过宽限后的因子 `max(0.1, 2^(-过期天数/30))`，半衰期 30 天和下限 0.1 均未调优，保证不是物理删除或零权重。明确失效/错误证据不适用这条下限，仍禁止召回。相关性原始分为零时，不靠长记忆权重凭空产生相关性。

约定提醒需独立 due_job/outbox，按本地约定时间调度，保持勿扰、冷却、发送有效期和事务预占。和新消息关联提醒分开记录类型，分享同一记忆的冷却规则。停机超过旧约定宽限不补发；过期旧事被新聊天提及时可做历史关联，但文案明确“这是过去的约定”，不能误导仍需履行。所有主动发送最后再检查版本、审核、只搜索开关与敏感模型一致性。

## 7. 反馈、每周抽检、自动降级

correct 在此设计中指明确内容更正，绑定更正前版本/证据及更正后 ID；不得和现有 `/correct` 的广泛标错停用行为仅按字符串互映。low_value、取消 low_value、outdated 独立绑定快照；outdated 表示准确但时效已过，不写 suppressed_evidence、不当事实错误。现场“有用/没用/不对”只携带固定反馈 ID；需验证用户、提醒和版本，不能借按钮调用任意命令。机器人若不支持交互按钮，使用明确的本机工作台入口或受限回执协议，不假设现有通道已有按钮能力。

每周约十条：在合格记忆中随机抽样，敏感层优先分配名额；保留种子、层和概率，不全靠模型挑“简单样本”。标注页与导出只绑定 ID/版本/证据哈希，不把模型结论预填为人工结果。抽到已修订版本重新出题，旧标签失效。校准页的离线一致率不自动触发产品决策。

生产现场反馈和每周抽检以滚动七天、当前有效的显式事实结论计算错误率，按同一反馈对象去重。分母不包含无反馈、low_value、outdated 或仅“没用”；分子只包含“事实不对/有误”。大于 5%（默认、未调优）时立即关闭所有主动提醒，保留搜索，并显示分子/分母、时间范围、触发版本和原因；无标签不能按零错误。小样本须显示不足，仍可保守停用出站；不会据此认定模型整体质量。回落低于阈值不自动恢复主动提醒，需用户核对后明确恢复。

## 8. 回填模型池与费用

按粗提、精修两个角色维护有序清单；每个模型自己的参数配置，不能继续沿用一个全局 thinking_mode。profile 仅允许能力白名单参数；default 不发送，off 仅在该精确模型被明确选用时按契约冻结；不支持或不确定参数不能从上一个模型复制。请求记录逻辑 code、实际快照、profile 版本、参数、提示词版本、预算账本和来源。

加入池需用户标记 free_tier_only_confirmed，并明确确认“已开用完即停、已看数据条款”。缺任一项拒绝加入/发送，不由 AI 代勾。默认 Token 上限为该模型用户填入额度的 90%，不自动发现免费额度，不把公开价格表当账号额度证明。

仅匹配 HTTP 403 且结构化错误 code 为 AllocationQuota.FreeTierOnly 时标 profile quota_exhausted，将未成功窗口移交下一个合格模型，不计业务提炼失败；其他 4xx 不自动重试。已发出的调用仍记账，没有可信 usage 仍保守占预留，不清零费用来强行切模型；全局或批量预算不足依然暂停。每个交接与领取在同一事务，未知结果不自动重发同一窗口，避免一个模型实际上已成功却重复花费。

免费额度模型仍按已确认的公开费率估算金额，另显示“免费额度，预期实付为 0”；estimated_cost 与 expected_cash 分开，不能用后者绕过预算。余额不足、免费额度不确定或数据条款未确认时停在队列，不转成付费兜底。粗提用用户选的快模型，精修用更强且不同的模型；能力/质量不能仅从单价或“强模型”名称推断。

## 9. 三十窗口烟雾批

持久运行，最多 30 个窗口，仍受单批 Token/金额、滚动全局、70% 批量份额和每模型 90% 限制。每次返回及窗口结束更新统计；任一条件暂停后续调用：合法结算率 <90%、空窗口率 >70%、单窗口总 Token >基线两倍、D3xx 窗口失败率 >20%。基线暂为 2600（未调优），两段及敏感双审核用量合计计入窗口；未知 usage 单独停用，不能按零占用。一个窗口多个 D3xx 只计一次窗口失败，另报事件数。

已明确识别的免费额度耗尽不计模型质量失败率，但保留账本占用、交接次数和结果未知状态。统计从首个可判定样本计算，故首窗为空可能触发保守暂停；不暗自加入预热豁免。若要最少观察数或阶段独立基线，需在审阅草案时明确，不由执行器自行调宽。烟雾结果不能自动开启长期批量或主动提醒。

## 10. 分阶段验收与审阅点

先审阅两份提示词和日期/状态设计；再用合成输入验证候选隔离、日期边界、敏感双审核、账本并发和额度切换。其后才另行授权真实实验 A、三十窗口烟雾批和新模型。一次性校准只整理用户明确标注，不让模型代填。

待审阅确认：提示词是否保留 v3 过滤；两位敏感审核员的实际模型身份；相对日期不明确的保守行为；临期/衰减和 5% 参数（均未调优）；烟雾从首个样本触发是否过于保守；候选拒绝/过期在界面上的解释。本文件不替用户作这些判断。
