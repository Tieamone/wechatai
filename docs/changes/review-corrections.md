# PR #18 后的审阅修正

本次不修改 schema，不在真实库升级，不启动真实应用，不调用模型，不转换旧留存。

实验执行前在创建 receipt 和 batch_run 前预检下一次调用的全局、批量比例与单轮 Token/金额预算，估算与现有 invoke 一致；预检不足时零调用退出且不占幂等名额。真正发送仍由原子 reserve 再检查，预检不能替代预占。是否禁止同清单重试只以该清单对应的 usage_ledger 调用记录为准，不能以文件是否存在推断已花费。即便账本结果为 released，本工具也按“已有调用记录”保守禁止重试，不声称必然已被供应商计费。只有完全没有调用记录的失败可复用清单和旧空运行重试。

low_value 与 clear_low_value 追加到同一版本化反馈表，保留记忆/证据快照。读取最后一条有效价值动作，取消恢复未知价值，既不变成“有价值”也不改变人工确认或 suppressed_evidence。评估工具同步遵守最后有效动作。

D102 且 content-type 为 text/* 时最多保留 2048 字节的本机前缀（UTF-8 截断时舍弃末尾不完整字符）；application/json 损坏仍不保留原文。D106 保持先白名单再截断；网页仍只返回元数据。文本前缀可能含网关文本或敏感信息，按原始聊天级别保护，沿用原有数量/总大小上限。

`tools.migration_rehearsal` 用只读源连接生成临时数据库，测试真实数据副本 v22→v24、旧列指纹/行数、integrity_check、foreign_key_check、自动备份以及恢复后二次升级。只保留无正文报告并删除本轮临时副本；不复制账号/密钥配置，不改真实库。真实业务统计和行数只保存在本机 private/ 和用户交付报告，不进入公开源码。
